# 项目要求摘要

> 完整要求以教师发布的《题目.docx》为准，本文件用于团队内部对齐。

## 项目定位

基于 Open WebUI 开发一门具体课程的专属 AI 助教，帮助学生理解知识点、复习与自测。主要使用模型配置、系统提示词、知识库、RAG 与工具扩展能力。

## 五个核心模块

### 1. 系统部署

- 完成 Open WebUI 本地或服务器部署；
- 接入至少一种大语言模型。

### 2. 课程知识库

- 来源：课程讲义/课件、实验指导书、教材节选、参考资料、自编知识点文档、示例代码及常见错误说明；
- 数量：不少于 8 个文件，或资料总量不少于 30 页；
- 组织：按章节或知识模块分类，至少包含 3 类资料；
- 回答课程问题时优先依据知识库，并给出资料引用；
- 库内没有的信息要明确回答“不确定/资料中未找到”，不得编造。

### 3. 课程 AI 助教

- 在 Open WebUI 中创建课程专属模型/智能体；
- 支持知识问答、通俗解释、按学生水平调整难度、例题与思路、按章节出题、答案分析与改进建议、来源引用、超纲提示；
- 系统提示词需明确：身份、课程范围、回答格式、引用要求、学术诚信、无法确认时的处理方式；
- 不得直接代写整份作业，作业题应给提示、思路和分步指导。

### 4. 自定义扩展功能

- 每组至少完成 1 个可调用的扩展（练习题生成、随机抽题、客观题判分、学习计划、章节查询、测试用例生成、先修关系查询或其他教师认可功能）；
- 有明确的输入输出，能在对话中调用；
- 建议用 Workspace Tool、Skill 或外部 API 实现；
- 仅用提示词模拟不算完成。

### 5. 系统测试与评价

- 设计不少于 15 个测试问题，覆盖：5 个知识问答、3 个综合分析、2 个库外问题、2 个出题/批改、2 个工具调用、1 个异常输入；
- 记录每个问题的输入、AI 输出、引用是否准确、答案是否正确、问题与改进方式；
- 至少做一次优化前后对比（提示词/知识库/切分/检索参数等）。

## 提交物

- 源码；
- Git 提交记录及仓库链接；
- 与 Codex 的交互记录；
- 项目总结报告。
