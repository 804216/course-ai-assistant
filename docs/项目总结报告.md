# 《基于 Open WebUI 的课程专属 AI 助教》项目总结报告

> 最近更新：2026-09-08
> 课程：林子雨《Python程序设计基础教程（微课版）》（第 1–15 章）
> 团队：王宇航 / 孙建奇（知识库 & AI 助教）、孟子豪 / 尹志学（自定义扩展 & 系统测试）、孟子豪（工程/集成/部署）
> 仓库：https://github.com/804216/course-ai-assistant

## 1. 项目概述

本项目基于开源平台 Open WebUI，为一门 Python 程序设计课程构建专属 AI 助教，用于帮助学生理解知识点、复习与自测。项目围绕题目要求中的五个核心模块展开：系统部署、课程知识库、课程 AI 助教、自定义扩展功能、系统测试与评价，并整理源码、Git 提交记录、与 Codex 的交互记录及本项目总结报告作为提交物。

## 2. 总体架构

```text
学生 / 教师
   │  浏览器访问 http://localhost:8080
   ▼
Open WebUI v0.11.0（本地部署，端口 8080）
   │
   ├── 专属模型：Python程序设计基础 AI 助教（python-ai-）
   │      ├── 底层对话模型：DeepSeek（deepseek-v4-flash，OpenAI 兼容）
   │      ├── 系统提示词 v1（docs/系统提示词.md）
   │      └── 能力：知识库检索/引用/章节查询/随机抽题/客观题判分（不联网）
   │
   ├── 知识库：Python程序设计
   │      ├── 资料：knowledge-base/（讲义、题目/答案、教学大纲、示例代码）
   │      └── RAG：本地 SentenceTransformers + Chroma 向量库（约 1.5 万条向量）
   │
   └── 自定义扩展（Workspace Tools）
          ├── chapter_query：章节资料查询
          └── quiz：随机抽题 + 客观题判分
```

## 4. 各模块成果

### 4.1 系统部署

- Open WebUI v0.11.0 以本地源码 + `local-deploy` 数据目录方式运行，端口 8080，本机访问 `http://localhost:8080`。
- 对话模型接入 DeepSeek（OpenAI 兼容，Base URL：`https://api.deepseek.com`，模型 `deepseek-v4-flash`）；
- 前端使用仓库构建产物；启动时设置 `DATA_DIR`、`FRONTEND_BUILD_DIR` 与 `WEBUI_SECRET_KEY`。

### 4.2 课程知识库（RAG）

- 资料规模：15 章讲义 PDF、30 个章节题目/答案 PDF、教学大纲 PDF、约 114 个示例代码文件及配套文本，均按“第 NN 章-章节名”归档于 `knowledge-base/`，满足“不少于 8 个文件或 30 页、至少 3 类资料”的要求。
- 入库状态：知识库“Python程序设计”共 169 个文件处理完成并关联，Chroma 向量库约 15,641 条向量。
- 嵌入与检索：本地嵌入模型 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`（中文友好、不消耗 API token）；chunk_size=1000、chunk_overlap=100、top_k=3；关闭“PDF 提取图片”以避免解析崩溃。
- 引用机制：回答优先依据知识库，按文件名/章节标注来源；库外问题明确回复“根据现有资料无法确认/超出课程范围”。

### 4.3 课程专属 AI 助教

- 模型 ID：`python-ai-`；名称：Python程序设计基础 AI 助教；绑定知识库“Python程序设计”；关闭联网搜索；开启引用与文件/代码能力。
- 系统提示词 v1 已归档（`docs/系统提示词.md`），明确身份、课程范围、回答格式、引用要求、学术诚信、超纲提示与不确定处理。
- 能力覆盖对照：

| 要求能力 | 实现情况 |
|---|---|
| 课程知识问答 | ✅ 知识库检索 + 引用 |
| 通俗解释 | ✅ 提示词要求“先通俗后正式” |
| 按学生水平调整难度 | ✅ 提示词内置自适应规则 |
| 例题/示例代码/解题思路 | ✅ |
| 按章节生成练习题 | ✅ 提示词 + 出题 |
| 学生答案分析与改进建议 | ✅ 遵守“不代写”原则 |
| 来源/引用 | ✅ |
| 超纲提示 | ✅ 提示词约束“仅提示不展开” |

### 4.4 自定义扩展

- **章节查询（chapter_query）**：输入章节号或名称，返回该章讲义/题目/答案 PDF 与示例代码清单；读取 `knowledge-base/` 真实目录。
- **随机抽题（quiz → random_questions）**：从 `tools/question_bank.json`（20 道结构化题）按章节随机抽取，默认不含答案。
- **客观题判分（quiz → grade_objective）**：输入题目 id 与学生答案 JSON，输出得分、总分、正确率与逐题判定。
- 三个功能均为真实工具（读取结构化数据、随机抽样、规则判分），非提示词模拟；代码已接入仓库 `tools/`，默认路径自动定位，克隆后无需修改路径即可使用。

### 4.5 系统测试与评价

依据题目要求完成 15 项必测并记录（`tests/测试题集.md`、`records/2026-09-05-扩展与测试记录.md`）：

| 类别 | 数量 | 结果 |
|---|---|---|
| 课程知识问答 | 5（K1–K5） | 正确且引用准确（第 4/5/6/7/9 章） |
| 综合分析 | 3（C1–C3） | 正确，引用准确；C2 遵守“不代写” |
| 知识库外问题 | 2（O1–O2） | 正确识别超纲，不冒充课程内容 |
| 出题/批改 | 2（E1–E2） | 符合要求 |
| 工具调用 | 2 必测（T1–T2） | 工具被真实调用并返回结构化结果 |
| 异常输入 | 1 必测（A1） | 稳定、礼貌处理乱码 |

主要结论：引用准确、超纲诚实、工具真实可调用。已知问题：回答普遍偏长；超纲场景仍偶有少量对照延展。改进方向：收紧提示词默认精简、超纲只提示不展开。判分工具（G1）、辱骂输入（A2）为选测项，以及“优化前后对比”尚未完成，列为后续工作。

## 6. 安全与数据管理

- API Key、密码、`webui_secret_key.txt`、`webui.db`、向量库与上传文件均**不提交仓库**，只在部署机 `local-deploy/` 中保存；换机重建方式为重新上传 `knowledge-base/` 或使用私有备份包迁移。
- `.gitignore` 已覆盖密钥、运行数据、虚拟环境与构建产物。
- 自定义工具路径改为“自动定位”，仓库中不包含任何机器专属绝对路径。

## 7. 遇到的问题与解决

| 问题 | 原因 | 处理 |
|---|---|---|
| 页面“Serving API only / 404” | 未设置前端构建目录 | 启动时设置 `FRONTEND_BUILD_DIR` 指向 `build` |
| PDF 入库报 reshape 错误 | 开启 PDF 图片提取 | 关闭图片提取后重新上传 |
| 知识库出现失败/待处理文件 | 误传 .doc/图片/重复文件 | 通过官方接口清理，保留 169 个 completed 文件 |
| 工具默认路径指向队友机器 | 代码含绝对路径 | 改为自动向上定位仓库内 `knowledge-base/` 与 `question_bank.json` |
| 含运行时数据的分支无法推送 GitHub | 单文件超过 GitHub 100 MB 限制 | 采用“源码/资料进 Git + 运行时私有备份”方案 |

## 8. 后续改进方向

1. 优化系统提示词：回答默认精简、超纲问题仅提示不展开；
2. 补测判分工具（G1）与异常/辱骂输入（A2）；
3. 执行一次“优化前后对比”（提示词或检索参数）；
4. 开放组员远程访问（校园网 IP 或 Tailscale）并记录访问地址；
5. 若需全量分发运行时，使用私有 Releases/网盘包并在目标机按部署说明恢复。
