## 1. 项目概述

本项目以 Open WebUI v0.11.0 为统一交互前端，围绕 Python 程序设计课程构建可在本机部署、可在前端自由选择、可追溯资料来源的课程 AI 助教。项目不仅保留了 Open WebUI 原有知识库和原生助教，还新增了独立版本化课程知识库、LangGraph 智能体、混合检索与重排序、课程工具、自动集成脚本和系统化测试。

当前实现覆盖以下核心目标：

- 建立按章节组织的课程专属知识库；
- 优先依据课程资料回答，并提供文件、页码或代码行号；
- 支持通俗解释、难度适配、示例、练习生成和答案点评；
- 对课程外问题和证据不足问题明确提示，不编造答案；
- 对整份作业、整套习题和可直接提交报告执行学术诚信拦截；
- 在 Open WebUI 中同时提供原生优化版助教和 LangGraph 助教；
- 提供章节查询、随机抽题和客观题判分等真实工具；
- 随仓库提供可直接复用的 v3 向量库和匹配嵌入模型，减少重复下载与重建。

## 4. 系统部署实现

### 4.1 部署方式

- Open WebUI 源码位于 open-webui；
- 启动入口为 scripts/start-open-webui-windows.ps1；
- Python 环境复用 open-webui/.venv，不重复安装同一套依赖；
- 前端构建产物位于 open-webui/build；
- 默认监听 0.0.0.0:8080，本机访问 http://localhost:8080；
- 数据、缓存、日志和临时文件均放在 open-webui/local-deploy 下，不再增加 runtime 目录层级；
- 启动脚本自动设置 DATA_DIR、FRONTEND_BUILD_DIR、模型缓存目录和临时目录；
- WEBUI_SECRET_KEY 保存在本机 local-deploy/webui_secret_key.txt，不进入仓库。

## 5. 课程知识库实现

### 5.1 源资料组织

知识库构建器只对 .pdf 和 .py 文件进行解析及向量化，字体、图片等其他文件只登记为资产，不进入向量库。

| 资料类型 | 文件数 | 保存策略 |
| --- | ---: | --- |
| 课程讲义 | 15 | 核心集合 |
| 习题题目 | 15 | 核心集合 |
| 示例代码 | 114 | 核心集合 |
| 教学大纲 | 1 | 核心集合 |
| 习题答案 | 15 | 独立受控答案集合 |
| 合计 | 160 | 46 个 PDF、114 个 Python 文件 |

资料按课程说明和第 1—15 章组织，所有源文件都有章节元数据，无未分类资料。当前构建状态为 157 个完成、1 个警告、2 个跳过；警告来自课程示例 pass.py 中用于教学展示的非完整语法片段，不影响整个知识库可用性。

### 5.2 分块与元数据

构建过程采用面向资料类型的切分策略，而不是把所有文件按统一字符数机械切分：

- PDF 保留章节、节标题和页码；
- Python 文件按代码结构和连续行组织，保留真实起止行号；
- 同一章、同一文件、相邻序号的知识块可在检索后重新合并；
- 每个知识块记录 file_id、text_hash、source、source_path、chapter_no、resource_type、ordinal、build_id 等元数据；
- 构建阶段检查空文本、重复文本哈希、缺失元数据和目录数据库与 Chroma ID 一致性；
- 只有目录数据库与两个向量集合均校验通过后，才更新 active.json 指向新版本。

## 6. 检索与召回优化

LangGraph 助教没有只把单个 Top 1 结果交给模型，而是按以下链路构造多证据上下文：

1. 对核心 Chroma 集合执行向量检索；
2. 对课程语料执行 BM25 关键词检索；
3. 使用加权 RRF 融合两路排名，BM25 默认权重为 0.3；
4. 从融合结果中最多选择 40 个候选；
5. 使用 BAAI/bge-reranker-v2-m3 对候选重新排序；
6. 默认保留重排后的前 12 个候选；
7. 将同文件相邻知识块合并为连续证据组；
8. 根据定义、列表、比较、代码或综合题类型，动态选择 3—8 个证据组交给回答模型；
9. 根据重排分数和查询词覆盖率执行证据充分性判断；
10. 证据不足时扩展查询并最多重试一次，仍不足则明确说明无法确认。

重排服务不可用时会自动降级到 RRF 排名，不会导致整个助教不可用。对“所有关键字”等完整清单问题，还增加了精确短语和清单锚点保护，避免表格型内容被普通语义相似度结果挤出。

回答生成后还会经过 grounding_guard 和 citation_guard：知识回答至少需要一个有效的 [资料N] 行内引用；未通过时根据原证据修订一次；最终删除无效引用并追加真实文件、PDF 页码或代码行号。

## 7. 课程 AI 助教实现

### 7.1 当前保留的三个助教

| ID | 类型 | 用途 |
| --- | --- | --- |
| python-ai- | Open WebUI 原有专属模型 | 保留旧实现和已有数据，作为历史对照 |
| python-course-ai-optimized | Open WebUI 原生优化版模型 | 绑定核心知识库及三个 Workspace Tool |
| python_course_langgraph | LangGraph Pipe 1.5.0 | 当前重点实现，显式编排检索、工具、约束与引用流程 |

三个助教可以在前端自由选择，不会覆盖 Open WebUI 其他模型和知识库。

### 7.2 LangGraph 节点与路由

LangGraph 图包含：

- normalize_input：处理空输入、超长输入和非法章节；
- rewrite_query：结合对话历史补全多轮追问；
- classify_intent：识别课程问答、概念解释、章节查询、练习生成、答案点评和越界请求；
- academic_integrity_response：在检索和生成前拦截整份作业、整套习题或可直接提交报告；
- retrieve_knowledge：执行混合检索、重排和证据组装；
- assess_evidence / expand_query：判断证据充分性并最多重试一次；
- chapter_tool / practice_tool：执行确定性的目录查询和练习抽取；
- compose_answer：依据多条证据组织答案；
- grounding_guard / revise_answer：检查回答是否有证据支撑并修订；
- citation_guard：校验引用标签和真实来源；
- invalid_response / out_of_scope_response / uncertain_response / error_response：处理不同失败路径；
- finish：向 Open WebUI 返回完成状态。

图在 Pipe 初始化时只编译一次，每次请求通过 Runtime Context 注入用户、模型、数据目录和阀门参数，减少重复构建开销。

### 7.3 教学策略与安全约束

- 支持零基础、初学者、进阶学习者和备考复习四档回答策略；
- 默认结构包括结论、解释或步骤、示例、来源、自我检查或下一步；
- 练习生成采用“章节—知识点—难度—题目—作答要求—提示”；
- 答案点评采用“正确之处—存在问题—改进建议—自我检查”；
- 课程系统规则作为不可覆盖策略加载，前端附加 system 消息只能补充风格；
- 明显体育、新闻、天气、股价等实时越界问题在模型分类前直接拦截；
- 知识库没有充分证据时，固定说明“根据现有课程资料无法确认”；
- 不直接代替学生完成整份作业，优先要求学生选择单题并提供已有尝试。

## 8. 自定义课程工具

部署集成脚本会通过 Open WebUI API 幂等注册以下三个 Workspace Tool，并将它们全部绑定到 python-course-ai-optimized：

| 工具 ID | 前端名称 | 函数 |
| --- | --- | --- |
| python_course_learning | Python课程学习工具 | get_course_outline、get_chapter_materials、sample_chapter_exercises |
| chapter_query | Python课程章节查询工具 | list_chapters、query_chapter |
| quiz | Python课程随机抽题与判分工具 | random_questions、grade_objective、list_bank_chapters |

chapter_query 读取 knowledge-base 的真实章节目录；quiz 读取 tools/question_bank.json，目前包含 20 道结构化题，覆盖 12 个章节。随机抽题和规则判分均由实际 Python 工具完成，不是提示词模拟。

LangGraph 助教还包含自己的内部章节与练习节点。这些内部节点属于图执行流程，不会作为独立 Workspace Tool 重复显示。

## 11. 安全与数据管理

- API Key、密码、webui_secret_key.txt、webui.db 和上传文件不提交仓库；
- 当前本机为兼容既有启动方式，从未提交的 .env.example 本地改动读取 rerank-key，并只在 Open WebUI 子进程中转换为 COURSE_RERANK_API_KEY；
- 正式共享前应将 rerank 密钥迁移到系统环境变量或不跟踪的本地 .env，并轮换已暴露的旧密钥；
- Open WebUI 普通运行数据和普通向量库继续忽略；
- 只对经过清洗、验证且用于课程助教的 v3 课程向量库及匹配嵌入模型设置 Git 例外；
- Git LFS 管理大型模型文件，避免普通 Git 对象超限；
- 参考答案集合与核心集合隔离，普通学生问答不默认访问答案。

## 12. 关键问题与解决方案

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| 页面显示 Serving API only 或 404 | 未设置前端构建目录 | 启动脚本设置 FRONTEND_BUILD_DIR，并支持重新构建前端 |
| 运行文件落到 C 盘 | 默认缓存和临时目录未统一配置 | 将 TEMP、TMP、HF_HOME、PIP/UV/NPM 缓存等全部指向 local-deploy |
| 部署路径存在多余 runtime 层级 | 旧部署目录结构重复 | 数据、日志、缓存和临时文件直接放在 local-deploy 下 |
| PDF 解析受异常图片影响 | 开启 PDF 图片提取 | 关闭不必要的图片提取，课程构建器直接解析文本 |
| 原向量库存在无效或污染数据 | 多次试验和无关文件共同写入 | 建立独立版本化 v3 知识库，并执行目录—向量一致性和污染检查 |
| 关键字完整列表召回失败 | 单纯向量检索不擅长完整表格和精确词项 | 增加 BM25、RRF、BGE 重排、锚点保护和相邻块合并 |
| 只给模型一个检索结果 | Top 1 容易缺失连续上下文 | 动态返回 3—8 个证据组，并按问题复杂度调整 |
| 回答出现无效引用 | 生成模型可能漏引或错引 | 增加回答依据检查、一次修订和最终引用校验 |
| 工具源码存在但前端只显示一个 | 原集成脚本只注册聚合工具 | 自动注册三个 Workspace Tool，并在校验脚本中强制检查 |
| Windows 合并时模型路径过长 | Hugging Face 快照目录层级较深 | Git 操作启用 core.longpaths，并使用 Git LFS 管理大型文件 |

## 13. 已知不足与后续优化

1. 教材口径与现代 Python 行为可能不同，例如字典插入顺序；后续应增加“教材口径 / 当前版本口径”双层说明。
2. 参数传递等术语仍需进一步约束，避免把对象引用语义过度简化为传统“传值/传址”。
3. 综合作业场景有时给出的代码过完整；后续应把首轮输出限制为接口、关键步骤和一条提示，收到学生尝试后再展开。
4. 初学者问题偶尔优先命中示例代码而非讲义定义，可增加“定义类问题优先讲义”的资料类型先验。
5. 无答案问题虽然能够拒答，但仍可进一步过滤不相关候选，减少内部无效检索。
6. 当前主要是单机部署；如需多人访问，还需配置校园网地址、Tailscale 或反向代理，并补充访问控制。

## 15. 总结

项目已经从“Open WebUI 原生知识库 + 单一提示词助教”发展为可复现的课程 AI 助教系统：课程资料经过结构化清洗和版本化构建，核心资料与答案隔离；检索采用向量、BM25、RRF 和重排模型的组合；LangGraph 对问答、工具、证据、引用、越界和学术诚信进行显式编排；前端可选择多个助教并使用三个真实课程工具；测试覆盖课程问答、综合分析、拒答、出题、批改、工具调用和异常输入。

当前实现已满足题目规定的主要功能和测试要求，并保留了可量化的自动验证与真实题实测证据。后续工作的重点不再是补齐基础功能，而是进一步提高术语严谨性、版本知识表达、回答简洁度和教学提示边界。
